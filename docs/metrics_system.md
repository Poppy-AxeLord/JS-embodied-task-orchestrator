# 指标体系设计（Metrics System）

> 本文严格依据技术契约 SPEC §7 编写，是「具身智能任务编排平台 + 数据闭环系统」的指标定义与决策口径文档。所有指标的计算口径均对应数据库 `tasks` 表字段（见 SPEC §2），由后端 `services/analytics.py` 计算、由前端「数据看板」(Dashboard) 可视化。指标体系是数据闭环「越用越好」飞轮的度量层：它既要回答「现在做得好不好」，更要驱动「下一步优化什么」。

## 一、为什么需要分层指标

一个自然语言任务编排平台的价值，最终体现为「用户随口说一句话，机器人就能把事情做对」。但「做对」是一个结果，背后由「听懂指令 → 拆解步骤 → 模拟执行 → 反馈闭环」多个环节决定。若只看一个总成功率，发现问题时无法定位是哪一环出了错；若指标过多又会淹没重点。因此我们采用经典的「北极星 + 过程 + 结果」三层结构：

- **北极星指标**：唯一的、统领全局的成败标尺，用于对齐团队方向。
- **过程指标**：刻画任务从理解到执行的中间环节质量，用于定位问题根因。
- **结果指标**：刻画用户价值与数据资产的沉淀，用于验证优化是否真正带来长期收益。

## 二、北极星指标：任务成功率

| 项 | 内容 |
|---|---|
| 定义 | 在一段时间内，最终成功完成的任务占全部任务的比例。 |
| 计算口径 | `任务成功率 = COUNT(success=1) / COUNT(*)`，对应 `tasks.success` 字段（0/1）。看板 `overview.cards.success_rate` 返回 0~1 浮点，展示时乘以 100 成百分比。 |
| 目标参考值 | 当前 Mock 历史数据约 72%~78%（见 SPEC §9 seed 设定）。短期目标 ≥80%，成熟期目标 ≥90%。 |
| 驱动决策 | 它是所有过程指标优化的「靠拢对象」。成功率掉头向下时，立即下钻到失败分类(SPEC §5)与过程指标，判断是理解、规划还是执行环节恶化。成功率是发版/接入新模型/调整拆解模板的最终验收门槛。 |

北极星指标只回答「好不好」，不回答「为什么」——这正是它需要过程指标支撑的原因。

## 三、过程指标：定位问题发生在哪一环

过程指标把「一句话到完成」的链路拆开度量，每一个都直接对应链路中的一个环节。

| 指标 | 定义 | 计算口径（数据库字段） | 目标参考值 | 如何驱动迭代决策 |
|---|---|---|---|---|
| 拆解准确率 | 任务拆解步骤被用户接受、未发生理解偏差的比例 | 近似为 `1 - (理解失败任务数 / 总任务数)`，理解失败即 `tasks.failure_category = '理解失败'`；亦可用人工修正率（`is_golden` 经修正的占比）反推 | ≥90% | 偏低说明指令理解/拆解模板有歧义。决策：补充该类指令的示例(SPEC §6)、优化 Prompt、为高频歧义指令固化定制模板。 |
| 平均步骤数 | 每个任务平均拆解出多少个原子技能步骤 | `AVG(tasks.step_count)` | 5~8 步（视任务难度） | 异常偏高说明拆解冗余、绕路；偏低可能漏步骤。决策：精简拆解逻辑或补全关键步骤（如缺少 `Confirm` 人工确认）。 |
| 平均重试次数 | 每个任务执行过程中平均触发的重试次数 | `AVG(tasks.retry_count)`，重试由 executor 在步骤失败时触发(SPEC §9) | <0.5 次 | 偏高指向执行环节不稳定（抓取掉落等）。决策：加固对应技能、引入 `Retry`/`Confirm` 兜底、为高风险技能补数据。 |
| 人工介入率 | 需要人工确认或修正才能闭环的任务比例（Human-in-the-loop） | `COUNT(needs_review=1) / COUNT(*)`，对应 `tasks.needs_review` | 逐版下降，长期 <10% | 居高不下说明系统自动化能力不足、用户负担重。决策：把高频人工修正的步骤沉淀为优质样本反哺模板，降低同类任务再次介入。 |
| 平均执行时长 | 任务从开始到结束的平均耗时 | `AVG(tasks.total_duration_ms)`，对应 `overview.cards.avg_duration_ms` | 在保证成功率前提下逐步下降 | 时长与步骤数、重试次数强相关。决策：先看是否被冗余步骤或重试拖累，再针对性优化；策略对比(llm vs rule)中作为「速度」维度。 |

过程指标的价值在于：当北极星指标下滑，可以逐列扫描这张表，快速锁定是「没听懂(拆解准确率↓)」「想复杂了(步骤数↑)」「手不稳(重试↑)」还是「太慢(时长↑)」。

## 四、结果指标：衡量长期价值与数据资产

结果指标回答「优化是否带来了真实、可累积的收益」，是数据闭环飞轮是否转动的证据。

| 指标 | 定义 | 计算口径（数据库字段） | 目标参考值 | 如何驱动迭代决策 |
|---|---|---|---|---|
| 用户满意度 | 用户对任务完成质量的主观评分均值 | `AVG(tasks.rating)`（1~5，对应 `overview.cards.satisfaction`，空值不计入） | ≥4.0 | 满意度与成功率背离时（成功但评分低）说明「做完了但没做好」。决策：关注体验细节（轻拿轻放等约束遵守度），优化约束生成。 |
| 优质样本积累数 | 经人工确认/修正、标记为高质量的样本累计数量 | `COUNT(is_golden=1)`，对应 `tasks.is_golden` | 持续单调增长 | 这是数据资产的核心。增长停滞说明闭环没在沉淀价值。决策：优化 HITL 修正入口，让人工修正更顺畅，把样本沉淀为拆解模板。 |
| 闭环优化条数 | 系统基于数据自动生成的可执行优化建议数量 | `services/recommendation.generate_suggestions()` 生成的条数（SPEC §8 `/api/dashboard/suggestions`） | 每个分析周期 3~6 条 | 这是「数据→洞察→行动」的产出。决策：建议被采纳后回看相关过程指标是否改善，形成验证。 |

## 五、指标看板如何驱动「发现问题→定位原因→优化→验证」决策闭环

指标体系不是用来「看」的，而是用来「决策」的。数据看板(Dashboard)按下面四步串起一个闭环：

1. **发现问题（北极星 + 4 张指标卡）**：Dashboard 顶部 4 个 `MetricCard`（总任务数 / 成功率 / 平均时长 / 满意度）与近 30 天趋势图(SPEC §8 `overview.trend`) 提供总览。当成功率折线掉头、或满意度下滑，即触发排查。

2. **定位原因（过程指标 + 失败分析）**：下钻到过程指标区与 `FailureAnalysis` 组件——失败原因 Top10 柱状图、5 类失败占比饼图(SPEC §5 配色)、分类趋势图(`/api/dashboard/failures`)。据此判断是「理解/规划/执行/感知/环境」中哪一类在恶化，并结合平均步骤数、重试次数、人工介入率确认环节。

3. **优化（闭环优化建议）**：`/api/dashboard/suggestions` 把数据洞察转成带 `priority/evidence/metric` 的可执行建议（如「感知失败占比 35%，建议补充遮挡场景数据」）。每条建议都附数据证据，确保优化有的放矢，而非拍脑袋。同时通过 HITL 修正沉淀优质样本(`is_golden`)反哺拆解模板。

4. **验证（回看指标 + 策略对比）**：优化上线后，回到看板观察相关过程指标与北极星指标是否改善；借助策略对比(`/api/dashboard/strategy-compare` 的成功率/耗时/雷达图)横向验证新策略是否优于旧策略。若改善则固化，否则回到第二步重新定位。

如此循环，每一轮都让优质样本更多、拆解更准、成功率更高——这正是数据闭环「越用越好」飞轮在指标层面的体现：**北极星指标对齐方向，过程指标定位根因，结果指标确认资产沉淀，看板把四步串成可持续滚动的决策闭环。**
