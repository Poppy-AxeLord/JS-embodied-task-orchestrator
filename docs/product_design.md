# 产品设计文档 · 具身智能任务编排平台

> 文档版本：v1.0　|　适用产品：自然语言任务编排平台 + 数据闭环系统　|　受众：PM / 算法 / 测试 / 运营

---

## 一、产品定位与价值主张

**一句话定位**：让任何人用一句中文自然语言，就能把意图编排成具身机器人可执行的原子技能流程，并通过"执行—反馈—分析—优化"的数据闭环，让机器人**越用越聪明**。

当前具身智能（Embodied AI）落地的核心痛点不在于"机器人能不能动手"，而在于三道断层：**意图断层**（人说的话与机器能执行的动作之间缺少可靠翻译层）、**可解释断层**（执行失败后说不清"为什么失败、是哪一环"）、**进化断层**（每次失败的数据白白浪费，系统不会自我迭代）。

本平台用一条主线打通三道断层：

- **自然语言 → 结构化任务**：把"把红色的杯子放到桌子右边"翻译成 `MoveTo → Recognize → Grasp → MoveTo → Place` 的可执行步骤序列，每一步都映射到 25 个标准原子技能之一。
- **执行可观测**：2D 仿真 + 逐步日志 + 失败 5 分类（感知/理解/规划/执行/环境失败），让每一次执行都可回放、可归因。
- **数据可沉淀**：每条任务自动落库，失败任务进入 Human-in-the-loop 人工修正队列，修正后的样本标记为"优质样本"，反哺拆解模板与模型。

**价值主张**：把机器人调试从"工程师写脚本"降维成"业务人员说人话"，把试错成本转化为可复用的数据资产。

## 二、目标用户与角色

| 角色 | 核心诉求 | 在平台中的高频动作 |
|---|---|---|
| **产品/业务（PM）** | 不写代码就能验证机器人能力边界、定义任务 | 在「任务编排」用自然语言下指令、看拆解流程图、跑仿真演示 |
| **算法工程师** | 评估拆解质量、对比 LLM vs 规则策略、定位失败根因 | 「数据看板」看失败分类与雷达对比、「执行模拟」做策略对比 |
| **测试工程师** | 批量验证、积累回归用例、把失败固化为样本 | 「任务历史」回放步骤日志、HITL 修正、沉淀优质样本 |
| **运营** | 监控线上健康度、产出迭代决策、汇报指标 | 「数据看板」看北极星成功率与优化建议、导出趋势 |

四类角色共享同一份数据，但消费视角不同：PM 关注"能不能做"，算法关注"做得对不对"，测试关注"稳不稳定"，运营关注"整体在变好吗"。

## 三、核心使用场景

1. **能力探索（PM）**：新业务接入前，PM 用 10 条预置示例与自定义指令快速试探机器人的拆解能力，判断该场景是否值得投入。
2. **策略评估（算法）**：同一指令分别用 LLM 拆解与规则拆解执行，通过成功率、平均耗时、重试次数、步骤精简度、满意度五维雷达图做 A/B 决策。
3. **失败归因（算法/测试）**：当成功率下滑时，从失败 Top10 原因与 5 类占比饼图下钻到具体任务，回放步骤日志定位是"看错了（感知）"还是"想错了（规划）"。
4. **样本沉淀（测试）**：失败任务进入 HITL 队列，测试人员在弹窗中拖拽修正步骤、重选失败分类，提交后该任务标记为优质样本（`is_golden`），成为下一轮拆解模板的训练素材。
5. **健康度监控（运营）**：每日查看北极星指标（任务成功率）、用户满意度与系统自动生成的 3-6 条带数据支撑的优化建议。

## 四、功能架构：五大模块如何协同

```
┌─────────────┐   parsed    ┌─────────────┐  ExecutionResult  ┌─────────────┐
│ ①任务编排    │ ──────────▶ │ ②执行模拟    │ ────────────────▶ │ ③数据看板    │
│ TaskEditor  │             │ Execution   │      落库 record   │ Dashboard   │
└─────────────┘             └─────────────┘                   └─────────────┘
      ▲                            │                                  │
      │   拆解模板/优质样本反哺       │ 失败 needs_review                 │ 优化建议
      │                            ▼                                  ▼
┌─────────────┐   修正 corrected ┌─────────────┐    驱动迭代     ┌─────────────┐
│ ⑤系统设置    │ ◀────────────── │ ④任务历史    │ ◀────────────── │   决策回路    │
│ Settings    │   策略/技能配置   │ History+HITL│                └─────────────┘
└─────────────┘                 └─────────────┘
```

- **① 任务编排（TaskEditor）**：意图入口。自然语言 + 策略选择 → 调用拆解服务产出结构化 `ParsedTask`（目标 / 约束 / 步骤 / 异常处理四区）。
- **② 执行模拟（Execution）**：把 `ParsedTask` 在 2D 俯视仿真中逐步播放，产出 `ExecutionResult` 并落库；失败时按 5 分类归因，约 1/3 失败任务进入人工介入队列。
- **③ 数据看板（Dashboard）**：消费全量历史，呈现北极星/过程/结果三层指标、趋势、失败分析、策略对比与可执行的优化建议。
- **④ 任务历史（History + HITL）**：全量任务可检索、可回放；失败样本经人工修正升级为优质样本。
- **⑤ 系统设置（Settings）**：配置大模型（OpenAI/通义千问/智谱/Mock）、仿真参数、数据保留策略与技能库增删改查。

五大模块构成一个**有向闭环**：编排产生数据，执行检验数据，看板洞察数据，历史修正数据，设置调优策略——修正后的样本与策略再次作用于编排，形成"越用越好"的飞轮。

## 五、关键用户旅程：从输入指令到优化迭代

以 PM + 算法协作为例的端到端动线：

1. **输入**：PM 在任务编排页点击示例"分拣所有蓝色的方块到 A 区，红色的放到 B 区"，选择 LLM 策略，点击「拆解任务」。
2. **拆解**：系统返回 `ParsedTask`，流程图以彩色节点展示 `Scan → Recognize → CheckColor → If → Grasp → Place → Loop` 等步骤，PM 可拖拽排序、增删、编辑参数。
3. **执行**：点击「去执行」跳转执行模拟，2D 仿真中机器人逐步移动、抓取、放置，右侧实时日志显示每步状态与耗时；若第 4 步抓取掉落，标记为"执行失败"。
4. **反馈**：执行结束弹出评分（1-5）与评价输入，PM 提交反馈，数据落库。
5. **归因**：算法在数据看板发现"执行失败"占比偏高，下钻到该任务，回放步骤日志确认是抓取力度问题。
6. **修正**：该失败任务出现在 HITL 队列，测试人员修正 `Grasp` 的 `force` 参数并提交，任务升级为优质样本。
7. **迭代**：看板的优化建议输出"执行失败占比 22%，建议补充易碎品抓取力控样本"；该优质样本反哺拆解模板，下一次同类指令拆解更稳。

一条指令，就此从"试一次"变成"留下一份可复用资产"。

## 六、差异化价值

- **不止于"能拆"，更在于"会归因、能评测"**：多数 demo 停留在自然语言转动作，本平台把失败拆成 5 个可定位的分类，并以"成功率 + 失败 5 分类 + 优质样本"构成一套面向具身智能的**评测体系（benchmark）**，让失败可解释、可统计、可改进，让能力可量化对比。
- **VLA 应用层定位清晰**：25 个原子技能构成 **VLA（视觉-语言-动作）模型的动作原语接口层**，把"语言意图 → 动作序列"的映射标准化，未来接真实 VLA 模型或真机时上层零改动。
- **指标驱动而非感觉驱动**：以任务成功率为北极星，配套过程指标（拆解准确率、人工介入率、平均重试）与结果指标（满意度、优质样本数、闭环优化条数），并可按任务类型 / 难度做分场景成功率对比，度量拆解的**泛化能力（generalization）**——每个决策都有数据支撑。
- **内建数据飞轮**：HITL + 优质样本机制让系统具备自我进化能力，使用越多、数据越丰富、拆解越准、泛化越好。
- **策略可对比**：LLM 与规则双策略同台竞技，不迷信大模型，用五维雷达客观选型（单次仿真看趋势，统计规律以看板 150+ 样本聚合为准）。
- **零编译、可演示**：纯 Python + 标准库 sqlite3，Apple Silicon 友好，Mock 模式下全功能开箱即用，便于快速验证与功能展示。

## 七、与真实机器人系统的对接设想

平台采用"编排层 / 执行层"解耦设计，当前执行层为 2D 仿真，未来可平滑替换为真实机器人或高保真仿真（Isaac Sim / MuJoCo）：

- **技能层即 VLA 动作原语接口层**：25 个原子技能（`MoveTo`/`Grasp`/`Recognize` 等）构成一层标准化的**动作原语接口层（action primitives interface layer）**，天然对应机器人 SDK 的动作原语或 ROS Action，也对应 **VLA（视觉-语言-动作，Vision-Language-Action）模型**的离散动作输出。届时只需把仿真执行器 `simulate_execution` 替换为真实的 VLA 推理 / 技能执行驱动，上层编排、评测与闭环完全不动。
- **感知接入**：`Recognize`/`Locate`/`Measure` 等感知类技能对接真实视觉模型（如目标检测 + 位姿估计），失败分类中的"感知失败"直接由真实置信度阈值触发。
- **闭环与评测口径不变**：无论执行来自仿真还是真机，落库、失败归因、HITL、优质样本沉淀的数据闭环逻辑，以及"成功率 + 失败 5 分类 + 泛化度量"的**评测体系（benchmark）**完全复用，真机数据可直接进入同一看板与飞轮，天然支持 **Sim2Real（仿真到现实迁移）**后的效果对齐评估。
- **安全兜底**：`Confirm`（人工确认）与 `Notify`（通知）作为控制类技能，为真机部署提供 Human-in-the-loop 安全闸门。

## 九、产品理念总结

本平台的本质不是一个"机器人遥控器"，而是一套**让具身智能持续进化的数据操作系统**。它把人类意图、机器执行与失败经验统一进同一个可观测、可归因、可沉淀的闭环里——每一次使用都是一次训练，每一个失败都是一份资产。这正是它区别于一次性 demo、能够长期产生复利价值的根本所在。
